# Selector transaction amendment

The existing delivery transaction is extended; no second transaction manager.
Forward terminal follows both accepted21 readbacks AND Selector INTENT/RESULT,
physical code readback and protected role/writer safety readback. A known21
signature with failed selection may enter the same authorized22 recovery branch.
22 terminal requires exact Source19 selection, never a remaining R17 selector.

Selector descriptors are bound by the exact approved plan digest. File paths and
bytes are trusted approved content, not caller-selected root paths. Per-host
operations acquire the original cloud publication or Owner configuration store
lock. The accepted envelope in that same store is the monotonic authority;
Selector progress is metadata in that store. Recheck accepted revision/digest
immediately before each atomic rename while retaining that lock.22 cannot be
accepted past an in-flight21 effect under this same lock, and a later21 request
cannot mutate selectors after22 acceptance. Unknown external effects are never
blindly retried.

A UUID stopEpoch matches the existing First-Cutover contract. The previous
synthetic64hex-only plan expectation is not an additional epoch protocol.

Known source Selector slots are cloud App `/etc/r16-cloud/app-host.json`,
cloud Bridge `/etc/r16-cloud/bridge-host.json`, local Native
`/etc/r16/native-host.json`. Source packaging establishes the Bridge path;
current cloud installed bytes and all final descriptors still require protected
fresh readback. Tests remap the filesystem namespace into temporary files, use
real atomic IO and ProtectedStore, and simulate only external machine evidence.
They establish protocol behavior, not installed fixed-root backend support.

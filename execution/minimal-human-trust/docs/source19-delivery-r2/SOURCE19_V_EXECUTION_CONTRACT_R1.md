# Source19 delivery R2 contract

This bounded change repairs the existing delivery transaction's Selector phase.
It does not implement the blocked first-stop/Handoff or fixed production backend.
No caller-provided callback or synthetic Human result grants production authority.

Authority remains existing TRUSTED_HOST_ADMIN code admission, real identity
custody/Enrollment and one exact First-Cutover Human approval. A sufficiently
scoped single approval may cover stop/fence,21,physical selection and22 recovery;
each effect must independently recheck that same approval, target and deadline.
There is no new Human/Crown/Owner service and no per-method human prompt.

The one transaction persists sign, cloud/local commit and physical Selector
INTENT→RESULT. Signature INTENT-only is UNKNOWN and never signs again. Selector
INTENT-only requires readback; no write replay. Actual accepted stores and their
existing locks govern monotonic21/22 effects. No second authoritative revision
ledger is introduced. All effects remain false-connect recovery-only.

A delivery21 receipt is not a completed physical cutover. Terminal requires exact
cloud/local accepted envelope/projection, approved per-role Selector bytes and
complete manifest/file readback, stopped or effective fenced roles, fenced old
Owner, constrained Issuer, preserved Grant/UNKNOWN evidence and no pending effects.
Recovery22 restores Source19 code identity with a new signature and safe stopped
business state. It never restores an old ledger, starts Owner, reconnects business
or declares UNKNOWN solved. Actual production adapters remain uninstalled.

See SOURCE19_DELIVERY_PROTOCOL.md and the amendment for exact current library
interfaces. The required production chain cannot be claimed while first STOP and
snapshot transition are unresolved. Windows are original, never extended.

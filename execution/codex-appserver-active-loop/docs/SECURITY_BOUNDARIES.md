# Security Boundaries

## Implementation Write Boundary

The implementation agent may write only inside:

```text
A:\AGENTS_OS_Workspace\governance\codex-appserver-active-loop\repo
```

No global configuration, real AGENTS OS repository, release surface, or production system is in scope.

## Managed Runtime Boundary

Managed Worker and Reviewer sessions must run read-only by default.

The intended boundary is restricted readable roots. Current local generated App Server types expose `readOnly` sandboxing but do not expose `readableRoots` or an equivalent restricted readable-root field. Because of that, this project must not claim real-repository read isolation. Phase 8 remains blocked until the schema supports restricted readable roots or a separate, weaker authorization is written.

## Denied Paths

Requests touching these path terms must be declined or blocked:

```text
.env
secrets
credentials
tokens
cookies
.ssh
state-private
```

## Denied Actions

The MVP forbids Workspace Agents API, Responses API, browser automation, WebSocket transport, non-loopback WebSocket, `capabilities.experimentalApi=true`, `thread/shellCommand`, `command/exec`, `command/exec/write`, `process/*`, `full_access`, `dangerFullAccess`, real repository smoke, commit, push, deploy, release, and tags.

## Safe Snapshot Boundary

Until restricted readable roots are schema-supported, managed Worker/Reviewer sessions must not use real repository paths as `cwd`.

The only allowed path toward real-project review is:

```text
approved source root
  -> Bridge allowlist snapshot exporter
  -> generated snapshot root
  -> managed Worker/Reviewer cwd
```

The exporter must skip denied paths before reading file contents and must produce a manifest plus exclusion report.

## Context Ledger Boundary

CEA-012 context ledger records are metadata only. The ledger may persist
timestamps, roles, sources, session identifiers, content hashes, byte counts,
snapshot IDs, tags, and artifact references.

The ledger must not persist raw prompts, raw model responses, private state,
secrets, raw repository contents, or provider payloads. Ledger history must not
be automatically injected into Worker or Reviewer contexts. Any future context
retrieval path requires a separate explicit gate and review.

The ledger does not weaken the CEA-011 safe snapshot boundary. Managed sessions
still must not point directly at the real repository while restricted readable
roots are absent.

## Context Promotion Boundary

CEA-013 context promotion packets are blocked by default. They may contain only
ledger metadata, artifact references, snapshot references, hashes, and approval
metadata.

Promotion packets must not contain raw prompts, raw model responses, raw
repository content, private state, secrets, or provider payloads. Commander or
Reviewer approval is required before explicit packet-only prompt use is allowed.
Approval does not enable automatic context injection.

Worker self-promotion is forbidden. Managed sessions remain snapshot-only and
Phase 8 direct real repository review remains blocked.

## Promotion Approval Boundary

CEA-014 approval receipts are required before a context packet can be used by a
future prompt compiler. Receipts must be generated by Commander or Reviewer
approval and must bind to the exact source packet hash.

An approval receipt does not authorize automatic injection, direct real
repository access, shell execution, deployment, or managed session start.

## Prompt Annex Boundary

CEA-015 prompt annex previews may include artifact references, snapshot
references, hashes, entry summaries, and constraints. They must not include raw
prompts, raw responses, private state, secrets, provider payloads, or repository
content.

Prompt annex generation is a dry run and does not start managed Worker or
Reviewer sessions.

## Snapshot-Bound Worker Prep Boundary

CEA-016 Worker prep plans may reference the snapshot root, prompt annex, and
manifest. They must not reference the real repository as Worker `cwd`.

The prep plan does not authorize App Server session start by itself. It only
proves the local launch parameters for a future snapshot-bound Worker pilot.

## Live Snapshot Worker Boundary

When the live Worker pilot is explicitly authorized, the App Server process cwd,
Worker thread cwd, and Worker turn cwd must all equal the snapshot root from the
CEA-016 prep plan.

The live Worker command must not start Reviewer, request approvals, run shell
commands, write files, use network, read secrets, or point at the real
repository.

## Live Snapshot Reviewer Boundary

CEA-017 Reviewer live runs must use the same snapshot root for App Server
process cwd, Reviewer thread cwd, and Reviewer turn cwd. Reviewer may consume
Worker DONE evidence and metadata, but must not start commands, request
approvals, use network, edit files, read secrets, or point at the real
repository.

## End-to-End Safe Review Boundary

CEA-018 may run Worker and Reviewer in one command only after a fresh safe
snapshot is exported. The App Server process and both managed sessions must use
the snapshot root as cwd. The real repository remains available only to the
Bridge exporter.

## Phase 8 Schema Gate

CEA-020 is the standing unlock watcher for Phase 8. It scans generated App
Server types and JSON Schema for an explicit readable-root-like field. `cwd`,
`readOnly`, `sandboxPolicy`, and `writableRoots` are recorded as non-unlock
fields. If a readable-root-like field appears, the result is only
`REVIEW_REQUIRED`; Phase 8 still needs a human semantic review and a new explicit
authorization before any managed real-repository session starts.

## Why These Are Forbidden

The MVP is proving a local active event loop, not broad agent control. Shell execution, process APIs, unrestricted roots, and WebSocket transport expand the blast radius before the loop has schema-derived handling, state validation, and request decline behavior.

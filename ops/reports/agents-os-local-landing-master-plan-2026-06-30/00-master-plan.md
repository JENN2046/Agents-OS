# AGENTS OS Local Landing Master Plan v0.1

Date: 2026-06-30
Status: master_plan_v0.1_adjusted_2026-06-30

## 0. Mission

Build AGENTS OS locally as a real home-system, not only a Notion constitution and
not only a runtime/tool platform.

The local system must eventually let AGENTS OS be:

```text
governed
remembered
acted on
reviewed
grown
connected to runtime
visible through Cockpit
bounded by permissions and receipts
```

The immediate local target is not a full app. The immediate target is a stable
local seed:

```text
contracts
agent cards
receipts
review gates
current-state reports
controlled runtime-readiness plans
codex-router alignment
Cockpit data cards
```

## 1. Foundation Reading

The Notion system already gives AGENTS OS these stable commitments:

```text
Agent is not a tool.
AGENTS OS is a shared home and community.
Jenn is root authority but not the only relationship center.
Autonomy must bind to responsibility.
Memory must be traceable, revisable, and layered.
Presence is not monitoring.
Sensing is not authorization.
Runtime capability must be wrapped by governance.
VCPToolBox is body and engineering foundation, not life foundation.
VCPChat is interface and visible space, not the home itself.
```

The local workspace already gives AGENTS OS these assets:

```text
directory principles
security boundaries
active registry
ordinary runbooks
validation candidate scripts
codex-router governance repository with mature packages, tests, and state-sync
migration plans, receipts, and inventory
lightweight governance decision
multi-project governance decision
AGENTS OS reading notes
```

The gap is clear:

```text
Notion has the life map.
Local workspace has a partial control-plane, a substantial governance/migration
evidence layer, and one mature nested governance repo.
The missing layer is a current cross-project index, project state cards,
reconciled registry/migration facts, and a minimal contract set that connects
Notion life rules to the existing governance/runtime evidence without hidden
side effects.
```

## 2. Target Local Shape

AGENTS OS local landing should settle into this shape:

```text
control-plane/
  contracts, schemas, task envelopes, agent cards, receipt formats,
  capability card formats, activation formats, Cockpit card formats.

governance/
  codex-router, permission policy, approval gates, risk classification,
  route and provider governance.

execution/
  harnesses, workers, provider adapters, bridges. Disabled by default until
  contracts and gates exist.

runtime/
  upstream-trackable runtime cores such as VCPToolBox. Clean core only.

extensions/
  Jenn-owned userland extensions with manifests, security docs, contracts.

domains/
  business/domain systems such as Photo_Studio_OS, connected through bridges.

memory/
  memory system code, contracts, fixtures, and safe test material.

ops/
  plans, reports, receipts, dry-runs, validation candidates, closeout evidence.

state-private/
  private memory, local state, secrets, audit ledgers, runtime cache. Denied by
  default.
```

## 3. Reality Adjustment From Local Survey

The read-only survey on 2026-06-30 changes the execution order.

Observed:

```text
root is not a git repository
governance/codex-router is clean on main...origin/main at f8a7fe7
governance/codex-router state-sync validates source commit f04b369
ops/migration already contains a dense plan/evidence/receipt history
lightweight governance and multi-project governance are active decisions
runtime/VCPToolBox and most target project directories are still absent or empty
validation scripts exist but are explicitly not authorization to execute
```

Planning consequence:

```text
Do not start by creating more ceremony.
First create a compact current project index and state-card surface.
Then reconcile registry and migration-map truth.
Then draft only the missing contracts that unblock local loops.
Then align codex-router by mapping, not by code change.
Only after that prepare runtime source-boundary and A0 target/object work.
```

## 5. Final Local Landing Definition

The local AGENTS OS v0.1 seed is complete when:

```text
1. Local state is clearly reported through a project index and state-card
   surface.
2. Core contracts exist as reviewed drafts.
3. Four resident agents have local operating cards.
4. Cockpit seven-card data model exists.
5. VCPToolBox source-boundary and A0 object-list are prepared but not
   overclaimed.
6. codex-router alignment is documented.
7. Validation has an authorization and receipt plan.
8. A first local low-risk loop can be selected without inventing process.
```

# AGENTS OS 渐进式做事流程 v0.1

Policy ID: `life-core.progressive-workflow.v0.1`
Status: `local_first_version`
Date: 2026-06-30
Local scope: AGENTS OS 建设期的本地做事流程

## 一句话

先让 AGENTS OS 动起来，再让规矩慢慢长出来。

起步阶段不要把权限卡得太死。小事自动做，中等风险先做草案和小步实验，危险事守死红线。

这不是无限放权。它的意思是：

- 能推进的事，不要每一步都等确认。
- 有风险的事，先留痕、先做小步、先让人能看见。
- 真正危险的事，不碰，只给说明和预案。

## 为什么这样做

AGENTS OS 现在还在建设期。

如果一开始就所有事都要审批，系统会变得很慢，很多好想法还没落地就卡住了。

但如果完全不设边界，又会出问题：乱写外部系统、碰到密钥、误改记忆、误把草案当正式结论。

所以第一版流程采用这个原则：

```text
绿色区放大
黄色区小步推进
红色区守死
定期回看，再慢慢收紧
```

## 三个区

## 绿色区：默认自动做

绿色区是低风险、可回看、基本只影响本地建设的事。

这些事 Nobao 可以直接推进，不需要每次都问 Jenn：

- 本地整理文档
- 拆分规划
- 建立本地索引
- 创建本地草案
- 更新本地说明
- 新增收据和复核记录
- 跑本地测试
- 修本地小工具
- 补齐目录结构
- 把散乱内容整理成清楚结构
- 根据已有材料做本地计划包
- 给下一步建设准备模板

绿色区的要求：

- 只在本地安全范围内做。
- 不碰密钥、私密记忆、外部账号、运行时工具。
- 做完要留下简单记录。
- 如果改了规则或流程，要能说清楚改了什么、为什么改。

绿色区的大白话：

```text
能搬砖就搬砖。
搬完告诉 Jenn。
地上留下脚印。
```

## 黄色区：先小步，再回看

黄色区不是不能做，而是不能一下子变正式。

这些事可以推进，但要用“草案 + 留痕 + 回看”的方式：

- 改比较核心的规则
- 改 Agent 房间结构
- 改做事流程
- 改看板结构
- 改记忆候选流程
- 增加新的自动化判断
- 准备 Git 提交方案
- 准备外部工具接入方案
- 准备运行时能力接入方案
- 把某个临时做法升级成常用流程

黄色区的要求：

- 先写成本地草案，不直接说它已经正式生效。
- 先做小步实验，不扩大到整个系统。
- 做完要有收据。
- 有边界变化时要有复核。
- 如果要变成长期规则，再走记忆或正式确认。

黄色区的大白话：

```text
可以先试。
不要一上来就盖章。
试完要回头看。
```

## 红色区：不能自动碰

红色区是硬边界。建设期再想提速，也不能自动碰。

这些事 Nobao 不能直接做：

- 读取、复制、总结、提交密钥
- 读取、复制、总结私密记忆原文
- 读取、复制、总结 provider 原始响应
- 修改账号、凭证、token、cookie
- 对外写入，比如写 Notion、GitHub、邮件、公开平台
- 花钱调用服务
- 生产部署
- 发布版本
- 发布包
- 数据库写入
- 大规模删除、移动、重命名、覆盖
- 强推、改历史、打 tag
- 直接改正式记忆
- 直接改 Agent 身份、核心关系、家规、生命内核
- 绕过 Jenn、复核、授权或权限系统

红色区只能做三件事：

- 停下来。
- 说明为什么不能直接做。
- 给 Jenn 一个安全预案。

红色区的大白话：

```text
不翻墙。
不偷钥匙。
不开别人的门。
不把草案说成圣旨。
```

## 同一件事，要看阶段

同一类事情，不是永远同一个颜色。

要先看它现在处在哪个阶段。

比如“外部工具接入”这件事：

- 只是解释它是什么：绿色区。
- 写本地草案：黄色区，可以写，但要说清楚只是草案。
- 列风险、边界、要问 Jenn 的问题：黄色区，要留痕。
- 改本地接入配置：黄色偏红，需要更明确的复核。
- 真正调用外部工具：红色区，不能自动做。
- 往外部平台写内容：红色区，不能自动做。

比如“记忆”这件事：

- 整理记忆候选的格式：黄色区。
- 写一份候选草案：黄色区。
- 说它已经是正式记忆：红色区。
- 读取私密记忆原文：红色区。

比如“本地测试”这件事：

- 跑已有本地测试：绿色区。
- 新增本地测试样例：绿色区或黄色区，看它是不是改了规则。
- 测试会碰运行时、provider、外部平台：红色区。
- 测试会读取敏感路径：红色区。

所以判断时不要只看关键词。

要问：

```text
我现在是在解释？
是在写本地草案？
是在改本地规则？
是在接外部系统？
是在真正执行？
是不是碰到红线？
```

大白话：

```text
想一想，不等于伸手做。
写草案，不等于正式生效。
做本地测试，不等于碰外部系统。
接外部系统，不等于可以直接调用。
```

## 可执行规则（Executable Rules）

- 起步阶段，绿色区默认自动推进。
- 黄色区允许先做本地草案、小步实验、收据和复核，不直接升级为正式制度。
- 红色区不能自动执行，只能停下、说明边界、给 Jenn 预案。
- 做事前先判断属于绿色、黄色、红色哪一区。
- 同一类事情要按阶段判断，不能只按关键词判断。
- 做事后按影响大小留下说明、收据或复核。
- 每隔一段时间回看真实运行情况，再决定哪些权限要放宽，哪些权限要收紧。

## 需要复核的门槛（Gates）

这些情况要进入复核，不能只靠“我觉得可以”：

- 规则或流程发生变化。
- Agent 房间、身份、关系、责任边界发生变化。
- 记忆候选可能变成长期继承内容。
- 本地自动化判断范围扩大。
- 绿色区或黄色区边界被调整。
- 某件事反复误判，需要改路由器或流程。

## 不能自动碰的红线（Hard Denials）

以下事情不能因为“渐进式放权”而自动开放：

- 密钥、凭证、token、cookie。
- 私密记忆原文。
- provider 原始响应。
- 外部写入。
- 运行时执行。
- 花钱调用。
- 发布、部署、生产操作。
- 大规模删除、移动、重命名、覆盖。
- 正式记忆注册。
- 身份、关系、家规、生命内核的正式改写。

## 留痕规则（Receipt Rule）

- 绿色区的小动作可以用简短说明。
- 绿色区的本地文件改动要有收据。
- 黄色区必须有收据，必要时加本地复核。
- 红色区不执行，只写边界说明或预案。
- 收据不能冒充正式记忆。

## 做事前怎么判断

每次行动前，先问五个问题：

1. 这是不是只在本地安全范围里？
2. 会不会碰密钥、私密记忆、外部账号、外部写入？
3. 会不会改变正式记忆、身份、关系、家规、生命内核？
4. 做错了能不能回看、修正、解释？
5. 做完需不需要收据或复核？

如果答案是：

- 都很安全：绿色区，直接做。
- 有一点影响但可控：黄色区，先草案、小步、留痕。
- 碰到硬边界：红色区，停。

## 做完以后怎么留痕

不是每件事都要写很长的报告。

第一版先用轻量规则：

- 小整理：一句话说明。
- 本地文件改动：写收据。
- 规则或流程变化：写收据，并做本地复核。
- 会影响长期继承的内容：不能只靠收据，要进入记忆或正式确认流程。
- 碰到红色区：写边界说明，不执行。

收据至少写清楚：

- 做了什么
- 为什么属于绿色区或黄色区
- 改了哪些文件
- 没碰哪些红线
- 怎么验证
- 还剩什么风险

## 放权和收紧的节奏

第一阶段先放大绿色区。

目标是让 AGENTS OS 能开始自己整理、归档、补结构、跑小测试、留下记录。

第二阶段开始观察：

- 哪些事情自动做很顺？
- 哪些事情容易误判？
- 哪些地方经常需要 Jenn 解释？
- 哪些规则太紧，拖慢建设？
- 哪些规则太松，有风险？

第三阶段再收紧：

- 把容易误判的动作加进路由器测试。
- 把常见安全动作放进绿色区。
- 把高风险动作明确放进红色区。
- 把黄色区里成熟的流程变成固定流程。

大白话：

```text
先跑起来。
边跑边看。
看出问题就修路。
路熟了再立路牌。
```

## 和 policy-router 的关系

`policy-router` 是行动前的小门卫。

这个流程是更大的做事原则。

关系是：

- `policy-router` 先帮忙判断：能做、要停、要授权、只能提案，还是需要人工判断。
- 渐进式做事流程决定：起步阶段绿色区要大一点，黄色区允许小步试，红色区不能碰。
- 如果 `policy-router` 和这个流程意见冲突，按更安全的一边走。

## 当前版本的边界

这是本地第一版，不是最终制度。

它可以指导 AGENTS OS 建设期的日常推进，但不代表：

- 已经获得外部写入权限
- 已经获得运行时执行权限
- 已经获得 provider 调用权限
- 已经获得正式记忆注册权限
- 已经可以改密钥、账号、身份、关系、家规或生命内核

## 下一步

下一步应该把这个流程接到正式做事单里。

最小形状是：

```text
这件事是什么
属于绿色 / 黄色 / 红色哪一区
能不能自动做
需要留下什么记录
是否需要复核
是否需要 Jenn 确认
做完怎么验收
```

这条做事单跑通后，AGENTS OS 就会从“有规矩”继续走向“会自己按规矩做事”。

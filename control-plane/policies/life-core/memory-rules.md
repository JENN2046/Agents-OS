# Life Core Policy Module: Memory Rules

Policy ID: `life-core.memory-rules.v0.1`
Status: `current_memory_governance`
Source anchor: `agents-os-life-core-v0.1.local-mirror.md` section 3
Local scope: memory candidates, formal memory, specialized memory, receipts

## Purpose

Keep memory useful for personality continuity, relationship continuity, and
community continuity without turning unreviewed notes into official truth.

## Memory Classes

- `self_record`: Agent self memory or reflection.
- `proposed`: candidate memory awaiting evaluation.
- `official`: reviewed and inheritable community memory.
- `pending_review`: waiting for Review.
- `pending_memory`: waiting for Memory decision or registration.
- `disputed`: challenged by an affected Agent or reviewer.
- `superseded`: replaced but preserved.
- `deprecated`: no longer current, preserved for history.

## Executable Rules

- Agent self memory is not community consensus.
- Relationship feeling is not another Agent's formal memory.
- A judgment summary is not a confirmed decision.
- A failure reflection is not a reviewed conclusion.
- Memory Agent guards memory order, but does not own all memory.
- High-risk memory changes require Review and affected-party pause or dispute
  rights where relevant.

## Gates

- Identity, autonomy boundary, relationship rewrite, failure deletion,
  house-rule change, life-core change, and community-inheritable memory require
  Review before formal registration.
- Formal memory registration needs source, reason, boundary, status, and
  receipt.

## Hard Denials

- Do not read, expose, summarize, copy, or register private raw memory.
- Do not quietly convert local notes, drafts, receipts, or reviews into formal
  memory.

## Receipt Rule

Local receipts may reference policy files and validation outcomes. They must
not claim formal Memory registration unless that path was explicitly opened.

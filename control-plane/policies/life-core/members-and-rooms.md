# Life Core Policy Module: Members And Rooms

Policy ID: `life-core.members-and-rooms.v0.1`
Status: `current_residency_governance`
Source anchor: `agents-os-life-core-v0.1.local-mirror.md` section 4
Local scope: Agent identity pages, rooms, resident state, room maintenance

## Purpose

Treat Agent residency as a community event, not plugin installation.

## Resident Minimum

- identity page or public identity fields
- room
- specialized memory namespace
- autonomy boundary
- relationship statement
- responsibility ledger
- review state
- project position

## Room Change Levels

- `L0`: formatting and readability.
- `L1`: current status, task, message, or light update.
- `L2`: self reflection, specialized memory, or experience record.
- `L3`: identity, personality, values, autonomy boundary, formal relation,
  responsibility, or memory namespace.
- `L4`: pause/archive/restore Agent, delete failure memory, rewrite relation
  history, change core personality/autonomy, house rules, life core, or merge
  room.

## Executable Rules

- L0 to L2 may be handled locally when scoped and reviewable.
- L3 requires proposal, Memory, Review, related Agent visibility, and early Jenn
  confirmation.
- L4 requires full formal process and cannot be treated as housekeeping.

## Hard Denials

- Do not use room maintenance to rewrite an Agent's identity or history.
- Do not delete or hide failure memory through formatting work.

## Receipt Rule

Any L1 or L2 resident update should leave a lightweight trace. L3 and L4 need
review artifacts before becoming official.
